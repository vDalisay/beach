# C03 — Inventory order, checkpoints and result metadata

Status: **implemented and checked in gameplay scenes** on 23 September 2026 with Godot `4.6.1.stable.mono.official.14d19694e`, Compatibility/OpenGL, content `beach-content-5` / generator `manifest-1`. The save schema remains 1; the new fields are additive.

The player record now persists `bag_order` across waste and valuables. Collection and knife rescue append to it; throw preview and transfer use its last entry; table unload and faint release consume its chronological order and clear it. The existing trash and valuable lists remain owner lists and capacity checks still use their shared total. Invariants require the order to contain every bagged ID exactly once. Older snapshots lack the original interleaving, so load deterministically orders valuables before trash to preserve their previous trash-first throw behavior. It cannot reconstruct the actual old pickup order.

Pause offers three native checkpoint choices with saved time and completion progress. Checkpoint 1 retains the original `manual` slot name; Checkpoints 2 and 3 use `manual_2` and `manual_3`. Save and Save and quit write the selected slot. Autosave remains separate. The title's existing Load list shows all slots, and checksum/content validation and A/B generation fallback remain in `SaveService`.

The immutable completion receipt now records the one local participant, ruleset `solo-beach-1`, bag/hand/bin/rack settings at completion, and faint count. New runs start at zero; older snapshots use `-1` internally and emit an unavailable (`null`) receipt faint count rather than inventing history. The receipt still latches at the one-time completion boundary.
