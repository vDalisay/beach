# P06 — Seeded starting manifest

Status: complete on 22 September 2026.

## Outcome

- Starting a playable run now normalizes the entered seed, generates the complete logical manifest, creates all runtime records, and passes the definitions and state into `RunSession` before the beach or player is instanced.
- Every manifest contains exactly 5,700 required objects (5,400 waste and 300 reusable props) plus 40 optional buried valuables.
- The required subsets are exact: 300 buried ordinary waste (200 PMD and 100 general), 24 rescue attachments, 120 standalone residue records, and 60 dirty chairs/loungers. The starter section contains no tool-locked objective.
- Generation uses authored integer-millimetre cells and pile offsets. It does not instantiate meshes, run physics, or depend on scene spawn order.
- Content or capacity defects abort generation with a diagnostic instead of reducing an objective count.

## Determinism contract

Generator version is `manifest-1`; content version is `beach-content-1`.

Seed input is trimmed only at its edges, preserves case and internal characters, rejects C0/C1 control characters, and is limited to 64 UTF-8 bytes. Blank input receives one 128-bit random hexadecimal seed which is immediately placed back into the menu field and retained in `RunState`.

Each RNG stream hashes the compact canonical JSON array:

```text
[generator_version, content_hash, normalized_seed, section_id, stream_name]
```

Allowed stream names are `litter`, `props`, `piles`, `dirt`, `buried`, `rescue`, and `valuables`. The first 15 hexadecimal SHA-256 digits become the positive 60-bit Godot RNG seed. Definition files, definition IDs, dictionary keys used in canonical JSON, section IDs, family IDs, and pattern IDs are explicitly sorted before order-sensitive work.

The canonical manifest payload contains `generator_version`, `content_version`, `content_hash`, normalized `seed`, and rows sorted by immutable item ID. Its digest covers integer positions, fixed 0–15 orientation indices, subset/location fields, and authored pile metadata.

## Placement and record rules

- Each section has a versioned 32×24 authored grid at 1,400 mm spacing. Waste, props, and optional valuables use non-overlapping cell domains.
- Stable required IDs are `item:<section>:<five-digit ordinal>`; optional IDs are `valuable:<section>:<five-digit ordinal>`.
- Ordinary definitions are chosen by positive integer weights only among definitions compatible with the anchor pack. Special subset assignment replaces an existing quota row; it never appends to required totals.
- Buried records retain an integer reveal pose and a bounded burial depth. Rescue records are paired into 12 stable two-piece rescue IDs. Piles use the authored `fan_5`, `ridge_6`, and `scatter_4` layer patterns.
- `ManifestGenerator.create_run_state` creates one `ItemRecord` per row, converts millimetres and orientation indices once, and preserves the immutable manifest/hash separately from mutable runtime state.
