# C03b — distinct presses and service prompts

Status: **FIN-01 repaired and checked** on 24 September 2026. Baseline `dae3d1a`, Godot 4.6.1 stable Mono, Compatibility renderer, content `beach-content-8`. Runs below used separate temporary `%APPDATA%` profiles; no player save was used.

`InputReader` now records mapped one-shot press/release events before physics sampling. A real release rearms the action even if a new press arrives before the next physics tick. Distinct queued presses are consumed once each; a held press cannot repeat over multiple ticks. Continuous `pressed()` input still drives movement and vacuum. Context changes and disabled-player transitions discard queued world actions, and held actions stay blocked on return. Binding changes and controller disconnect clear stale edges. `Input.action_press()` retains the small fallback needed by existing scripted movement/scanner checks.

Station targets now expose a service verb separately from a rejection reason. `TargetLabel` appends the live Interact binding to that verb. The counter, tool rack, all 12 containers and three hotlines no longer store a literal `E:` prompt. Actual service rejections still come from the original action results.
