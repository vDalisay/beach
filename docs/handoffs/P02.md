# P02 — Definitions, item ownership and run state

Status: complete on 22 September 2026.

## Outcome

- `RunState` is the authoritative mutable run model; item views and scene-node lifetime do not own totals.
- `RunSession` owns one `RunState`, the concrete `ItemStore`, revision finalization, public signals, save requests, and deferred signal-triggered follow-up actions.
- Definition Resources cover items, tools, upgrades, and beaches. Services read shared definitions without mutating them.
- `ItemRecord` serializes every documented location by stable string name and retains ordered ownership, physics snapshot fields, dirt, burial, rescue, and attribution state.
- The main scene now creates a real empty `RunSession` with the local player instead of a generic placeholder Node.

## Mutation and publication boundary

Each ItemStore action validates player, item, definition, source state, capacity, and references before changing any list or record. A successful action updates both ownership sides, increments the run revision once, publishes signals, and requests save. Signal listeners see the new revision and completed ownership change. Any action requested by a listener returns `DEFERRED`, queues its callable, and executes only after all observers have received the first finalized publication.

P20 will insert progress/reward finalization immediately before the existing revision increment; it should not create a second public transaction.

## Snapshot representation

Snapshots contain plain Dictionaries, Arrays, strings, booleans, and finite numbers. Item locations are names such as `WORLD`, `BAG`, or `SLOTTED`, never enum ordinals. Transforms use 12-number basis/origin arrays and vectors use three-number arrays. Items and players serialize in sorted stable-ID order; bag and hand arrays retain gameplay order. Disk writing, migrations, checksums, and generation fallback remain P24 work.

```powershell

& $beachGodot --headless --path 'C:\Users\Home\Documents\beach' --editor --import

& $beachGodot --headless --path 'C:\Users\Home\Documents\beach' --quit-after 2
```

Observed result: `PASS: boot, asset_closure, ownership`, exit 0, with no GDScript errors.

The fixture uses PMD/glass/general waste, two one-hand props, one dirty two-hand chair, optional keys, and an attached rescue ring. It demonstrated:

- first collect commits revision 1 before its observer runs;
- an observer-requested bottle collect remains WORLD during the signal and commits afterward as revision 2;
- duplicate collection, attached-item collection, full-bag collection, and over-capacity chair holding all reject without changing snapshot bytes;
- bag order remains `waste:can`, then `waste:bottle` across JSON round-trip;
- two states sharing the same definitions remain independent;
- invariant validation returns no errors before and after snapshot restoration;
- freeing a presentation Node3D does not alter the required denominator.

## Known gaps

- P02 models only the owner lists exercised so far. Sorting, sealed-bag, slot, recovery-pile, progress, and save packets must extend the existing records and invariant validator rather than create parallel state.
- `try_throw` validates logical ownership and finite transforms; world obstruction checks belong to the P07/P09 physics flow.
- The main run has no generated manifest until P06 and no playable player/world until P04/P05.
