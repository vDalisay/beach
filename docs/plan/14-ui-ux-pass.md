# UI/UX pass — menus, HUD, prompts and text

Planned 25 September 2026 on `main` at `a8b7eea`. **Status:** U00–U10 implemented; evidence, departures and open issues are in [U-ui](../handoffs/U-ui.md).

The game already *plays* well: [J00–J14](12-game-feel.md) gave hover, hands, placement, tools and completion their motion. The interface around that play is still the default Godot look: grey panels, the fallback font, text-only prompts such as `Collect [Left Mouse Button]`, and a title screen on a flat colour. This plan gives menus, HUD and every piece of on-screen text one visual language, taken from the game's own wordmark and the Synty interface packs, so it sits in the same family as Tidy Farm, Too Many Toys and Supermarket Chaos. It also makes every button and menu move the way incremental games like *A Game About Feeding a Black Hole* do.

It is written for implementers who have not read the code. Every packet names its files, the nodes it keeps for existing callers and checks, and how to show it working.

## 0. Authority and boundaries

- **Presentation only.** No change to ownership, payments, completion, restoration, saves, capacities, reach, bindings, content or generation. UI reads state and calls the existing services, exactly as today.
- **Locked requirements stay locked.**
  - R24: the top-left HUD shows combined progress, then the prop and trash breakdowns, then money, in that order. The words *Completed*, *Props*, *Trash collected* stay, because they make truck-based credit explicit ([P22](packets/P22-ui.md)).
  - R29: every screen works with a controller alone; no sound.
  - D21: English, readable labels, colour-independent icons, UI scale 100–150 %, reduced motion.
  - D19: pause and booklet still pause the simulation.
  - P22: notices never cover the aim point or sorting targets; focus returns to the originating button when a modal closes.
  - R01: 60 fps on GTX 980-class hardware. The HUD redraws only on change; nothing in this pass runs per-frame layout.
- **Reduced motion** follows the J-plan rule: values take their final state at once; no bumps, tilts, slides, shakes, shines or particles; colour and icon states remain.
- **Test contracts.** The existing checks read some UI members and strings directly (see §9). A packet that changes one of them updates the check to the new UI in the same packet and keeps the check's intent. Node names that gameplay scripts look up (`UI`, `ProgressPanel`, `ContextPanel`, `GuidancePanel`, the meter and scanner paths) stay.
- **Assets.** Use the supplied Synty packs wherever they fit (§3). Make our own only where no pack asset exists or where a pack asset would clash with the brand. Licensed Synty files stay local and are regenerated by a staging tool, as the 3D art is.

## 2. UX principles

1. **World first.** HUD elements are outlined text and icons straight on the world, with no panels, like the reference games. Panels appear only for modal screens, and those blur the world behind them.
2. **Information at the point of need.** The object name and what you can do with it sit under the aim point. Bag and held objects sit bottom-right, tools bottom-left, progress top-left, hints top-right. Anything not needed right now is hidden (oxygen out of water, the detector readout without the detector, the scanner hint until the skill is learned, the whole world HUD while the sorting table is open).
3. **Glanceable numbers.** Big display figures for the one number that matters in each block; small captions for the rest. Every number rolls, every bar fills and shines (J09 keeps its behaviour).
4. **Icons plus words.** Every prompt shows the actual binding as an input icon *and* a verb. Every category, tool and currency has an icon; colour is never the only signal.
5. **Everything answers back.** Buttons lean in on hover, squash on press, spring back and throw a few sparkles. Screens slide in with a slight overshoot; lists enter one row after another. Rewards pop and burst. Motion is short (≤ 0.3 s), never blocks input, and disappears under reduced motion.
6. **One focus language for mouse and controller.** Hover and focus look the same, so a controller player always knows where they are.

## 3. Art direction

### 3.1 Brand

The wordmark (`marketing/steam/build_capsule.py`) is navy-rimmed sticker lettering with a gold and an aqua gradient, a parasol for the T, and four-point sparkles. The whole interface uses that language.

| Token | Value | Use |
|---|---|---|
| `navy` | `#0b2a44` | Outlines, rims, text on light fills, shadows |
| `navy_deep` | `#071a2c` | Modal tint, dark cards |
| `white` | `#ffffff` | Text on the world, sticker inner line |
| `gold` (top/mid/bottom/shade) | `#fff6cf` / `#ffd257` / `#ff9f1c` / `#c9570f` | Primary and hovered buttons, money, rewards |
| `aqua` (top/mid/bottom/shade) | `#ffffff` / `#bff6ff` / `#3fc6e6` / `#16799c` | Secondary accents, progress fills, selection |
| `sand` | `#fff3dc` | Card and booklet paper |
| `coral` | `#f25c54` | Danger, errors, "full" |
| `mint` | `#7ff5c8` | Success, placement (J ghost colour) |
| `amber` | `#e8b45a` | Blocked (J blocked colour) |

`scripts/ui/kit/ui_palette.gd` holds these constants; nothing else hard-codes a brand colour.

### 3.2 Type

Both families are OFL fonts shipped inside *INTERFACE Modern Menus*, so they are committed under `art/fonts/` with their licences.

- **Bungee** — display: logo-adjacent titles, big numbers, object names, verbs on prompts, button labels. Its chamfered caps match the wordmark glyphs.
- **Barlow Condensed** Bold / Medium — body: captions, descriptions, lists, settings rows. Condensed keeps HUD lines short.

On the world, text is white with an 8 px navy outline (at 720p base) and a soft navy shadow. On sand-coloured cards it is navy with no outline.

### 3.3 Components

- **Sticker box** (`StickerBox`, a scripted `StyleBox`): navy rim, white inner line, vertical gradient fill, soft drop shadow. Drawn as geometry, so it is sharp at any UI scale and resolution. Variants: gold (primary / hover / focus), cream (resting), aqua (selected tab), coral (danger), navy (dark card), paper (booklet page).
- **Buttons**: aqua sticker with white, navy-outlined Bungee at rest; gold when hovered, focused or pressed. Primary actions (Continue, Start, Resume, Buy) are gold at rest; secondary actions (Back, bindings, options) are paper with navy text. Disabled: grey-blue, no motion.
- **Bars**: navy capsule track with a gradient fill and the J09 shine.
- **Tabs, sliders, check buttons, option buttons, line edits, scrollbars, item lists** all share the same rim, radius and colours.
- **Frosted shade**: modal screens blur and tint the live game behind them instead of hiding it.

### 3.4 Iconography

| Need | Source |
|---|---|
| Glyph icons on the world (book, gear, star, check, warning, info, coin, trophy, home, arrows) | *Modern Menus* `Icons_ModernMenus_Flat/*_Stroke` (white with a dark rim — readable on sand and sea) |
| Reward and currency art (coins, stars, trophies, medals, gifts) | *Modern Menus* `Icons_ModernMenus/*_Ortho` (rendered 3D) |
| Input prompts | *Interface Core* `Icons_Input` — mouse, keycaps, Xbox buttons, D-pad, sticks (`_Underlay` versions have a dark rim) |
| Tools, items, props | Rendered at runtime from the game's own models by `IconStudio`, so an icon always matches what is in the hand |
| Sorting categories, the HUD trash count | *POLYGON Icons* 3D models (soda cup, apple, trash bin, glass), rendered by `IconStudio`; 38 models are staged for later use |
| Cursor | *Modern Menus* `Cursors` |
| Logo | The existing wordmark SVG (`title_wide.svg`), copied into `art/ui/` |

### 3.5 Motion

| Beat | Motion |
|---|---|
| Hover / focus in | scale → 1.06, tilt −1.5°, 0.14 s `TRANS_BACK` out; label turns white-outlined; gold fill |
| Hover out | back to 1.0 / 0°, 0.12 s |
| Press | squash to 0.93 in 0.05 s |
| Release / click | spring to 1.08, settle at 1.0 (0.25 s `TRANS_BACK`), 5–8 sparkles burst from the click point |
| Screen in | 0.26 s: alpha 0 → 1, scale 0.94 → 1, y +18 → 0, `TRANS_BACK` out; children stagger 0.04 s |
| Screen out | 0.14 s fade and scale 0.97 |
| Numbers | J09 rolling counts; the big completion figure bumps |
| Rewards | icon pop to 1.25, coin burst, confetti for sections and the finale |

All tween durations and amplitudes live in `UiKit`. Reduced motion skips every one of them.

### 3.6 Particles

*POLYGON Particle FX* supplies the textures (sparkle, soft spot, circle, ring, bubble…) and FX meshes (coin, star, heart); *Modern Menus* adds glow dots and star icons. The Unity prefabs cannot be imported, so each effect is rebuilt in Godot after the prefab's look: click sparkles, star and coin bursts and confetti in the UI layer (`CPUParticles2D`, pooled in `UiKit`), and self-freeing `FeelBurst` confetti, hearts and coins in the world (`CPUParticles3D`, capped like `FeelRing`). Title-screen bokeh and wordmark twinkles use the same textures.

## 4. Screen specifications

### 4.1 Title screen

- **Backdrop.** The real beach scene, instanced into a half-resolution `SubViewport` with its own world, with no litter and no run. A camera drifts along a slow looping tour: along the shoreline, out over the water looking back at the palms, past the pier and lighthouse. The picture is softly blurred and warmed, with a vignette.
- **Logo** top-centre, bobbing gently; sparkles twinkle around it.
- **Menu** left of centre: Continue (only with a usable save), New beach, Load, Settings, Quit. Buttons enter one after another. Focus starts on Continue when it is available, otherwise New beach.
- **New beach panel**: seed field (keeps the `first-shore` default), a dice button for a random seed, Start and Back.
- **Load panel**: the save list (seed, slot, date and progress per row); Load and Back.
- Bokeh and sparkle particles drift across the backdrop.
- **Loading curtain**: Start, Continue and Load build the run behind a curtain (wordmark, spinning Modern Menus ring, a gameplay tip) that is drawn before the build starts and fades away to reveal the beach, instead of freezing on the menu.

- **Top-left (R24 order):** big completion figure, bar with "COMPLETED · N LEFT", PROPS, TRASH COLLECTED, money with a 3D coin. Under it, the **area chip**: the nearest section's name, a thin bar and what is left there. It updates at 4 Hz with hysteresis and pops when the area changes or an item there is completed.
- **Top-centre:** notice pills (tips, sets, restorations) with an icon per tier. They sit in the free lane between the top-left block and the top-right column, and move above the aim point on short screens (150 % UI scale).
- **Top-right:** booklet hint chip; scanner chip once the skill is owned; the collection receipt card below them.
- **Centre:** J02 reticle; the target name under it with prompt chips (§4.3).
- **Bottom-left:** tool hotbar — one card per equipped tool with its rendered icon; the active one raised with a gold rim; the switch key under it; the tool name under the active card.
- **Bottom-right:** held objects (selected one larger, with a pointer) and their throw / cycle prompts; the bag counter with an icon and a capacity bar that goes amber and coral as it fills.
- **Bottom-centre:** oxygen gauge only when submerged; detector meter only with the detector out.

### 4.3 Target prompt

`DRINK CAN` in Bungee under the reticle, then one chip per available action: input icon + verb (`COLLECT`, `CARRY`, `PLACE`, `CLEAN`, `CUT`, `PICK UP`, `INTERACT`). Blocked targets show the reason in amber instead of chips, with the J02 shake. The block pops in (scale 0.9 → 1, rise 6 px) when the target changes, and swaps text in place when only the prompt changes. The icon follows the active device and bindings; an unmapped binding falls back to its text in a keycap.

### 4.4 Modal screens

Pause, settings, booklet, shop, rack and results all open over the frosted shade with the screen-in motion, and restore focus on close.

- **Pause:** sticker title "PAUSED", big Resume, Settings, checkpoint picker, Save checkpoint, Save and quit.
- **Settings:** tabs with icons (Controls, Graphics); rows with a label left and control right; sliders with value chips; toggles as sticker switches; the binding list shows input icons.
- **Booklet ("field notebook"):** paper card with icon tabs. Sections: one row per section grouped by zone, each with a progress bar and small chips for "in area", "awaiting collection" and "props to place". Discoveries: a grid of rendered item icons plus material chips, then the scanner filters. Skills: cards with icon, effect, price and a Buy button that bursts coins on purchase. Controls: action name + input icons.
- **Shop and rack:** the same cards, with the tool's rendered icon.
- **Sorting table:** themed top bar and bins; each bin shows its category icon, name and fill; action buttons show their input icons.
- **Results:** the J12 postcard in a sticker frame, gold "COAST RESTORED" title, confetti.

## 5. Architecture

New code lives in `scripts/ui/kit/`:

| File | Role |
|---|---|
| `ui_palette.gd` (`UiPalette`) | Brand colours and font paths |
| `sticker_box.gd` (`StickerBox`) | Scripted `StyleBox` for sticker panels and buttons |
| `ui_kit.gd` (`UiKit`, autoload `Ui`) | Attaches button motion to every `BaseButton` that enters the tree; screen-in / stagger / pop helpers; 2D particle bursts; custom cursor; holds the `SettingsStore` for reduced motion |
| `input_glyph.gd` (`InputGlyph`) | Draws the icon for an action's current binding on the active device |
| `prompt_chip.gd` (`PromptChip`) | `[glyph] VERB` row used by the target prompt, HUD hints, sorting and menus |
| `icon_studio.gd` (`IconStudio`) | Renders a 3D scene to a transparent texture once, then caches it |
| `frosted_shade.gd` + `shaders/ui_frost.gdshader` | Blurred, tinted backdrop for modals |
| `menu_backdrop.gd` | Title-screen beach `SubViewport`, camera tour and blur |

`tools/build_ui_theme.gd` builds `data/ui/beach_theme.tres` from the palette and is the only place the theme is edited; `project.godot` sets it as `gui/theme/custom`. `tools/stage_ui_assets.gd` extracts the chosen Synty sprites, input icons, particle textures and POLYGON Icons models from the local packs into `art/synty/ui/`, `art/synty/fx/` and `art/synty/icons3d/` (all git-ignored, like the rest of `art/synty/`).

## 8. Risks

| Risk | Mitigation |
|---|---|
| Scripted `StyleBox` drawing cost | Geometry is a few polygons per box and only redraws on change; profile the booklet and settings with many rows. |
| Screen-texture blur in the Compatibility renderer | Fixed-tap blur that does not rely on screen-texture mipmaps. |
| Title backdrop cost and load time | Half-resolution viewport; the beach scene is already preloaded; freed before the run beach is built. |
| `IconStudio` on first open | Renders one icon per frame, cached; the page shows the name until the icon lands; warm the equipped tools at run start. |
| Checks that read old UI text | Updated in the packet that changes the UI, keeping the same intent (§9). |

## 9. Existing checks that read the UI

`validate_ui` (HUD text, title focus and buttons, booklet structure, pause focus), `validate_interaction` and `validate_c01_input` (target text), `validate_purchases` and `validate_scanner` (booklet/shop rows), `validate_sorting`, `validate_sealing`, `validate_buried` (sorting members and focus), `validate_save` (title and load panel), `validate_payment` (toast text), `validate_completion` (notice and receipt lanes; results view), `validate_full_run` (hides `UI`), `run_checks` (settings focus). Gameplay scripts look up `ProgressPanel`, `ContextPanel`, `GuidancePanel`, `OxygenMeter/Panel/Content/{AirLabel,AirBar,Hint}`, `DetectorMeter/Panel/Content/{Distance,Strength}` and `ScannerOverlay/{SummaryPanel/Summary,Markers}`.
